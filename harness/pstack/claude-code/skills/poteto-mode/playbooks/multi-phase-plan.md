### Multi-phase plan

Write the plan for the operator to review.

1. Skip a separate plan when the change is small and its approach is obvious.
2. Settle technical questions with the [Prototype playbook](prototype.md). Surface unresolved product decisions.
3. Record the goal, dependency order, and one section per local change. Each section names its dependencies, paths, expected behavior, and check.
4. Specify the test, live scenario, or benchmark each change needs. Capture a baseline when claiming parity or a speedup.
5. Hand back the plan and the approval points. Wait before implementation when the user requested a plan only.
